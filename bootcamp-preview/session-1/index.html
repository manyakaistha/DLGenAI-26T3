Bootcamp Session 1 · Read the Data Before You Train

30 October 2026 · Data Understanding, Defect Exploration and Metrics

Open the interactive classroom presentation → Follow the core lesson in class; use the nine optional stops for deeper study. The 53-stop presentation includes nine notebook examples with direct section links and downloads. Save the slides for offline use from the slide index; Colab links need internet access.

A photograph is an input. A mask is an answer someone has drawn. A prediction is a proposed answer. This session makes those three objects concrete before introducing a large neural network.

These study chapters are written for students who need more support with Python, ML or DL. Each develops the definitions, mechanism, worked examples, implementation checks and practice needed to study independently. You can follow the core route without knowing calculus, convolutional networks or GPU programming. By the end, you should be able to explain a small mask calculation, inspect a real image–mask pair, and recognise a misleading validation result. These are steps toward a reliable project; no guide can promise a qualifying score.

Start here

  1. Open Guide 1: arrays, images and notebooks. If indexing is unfamiliar, do its three small exercises before opening a data folder.
  2. Download the foundations notebook and run it from the top. It works with tiny teaching examples and needs no competition download or GPU. Its paired Python file is useful when a notebook is unavailable.
  3. Open the real-data practice notebook only after reading the practice dataset instructions. Its paired Python file follows the same sequence.
  4. After the audit, use the starter pixel-model notebook to train a small image-dependent baseline. Its paired Python file uses the same held-out split; the core ideas are explained in Guide 7.
  5. Keep a short evidence log: question → check → observation → explanation → next question. A printed number without its denominator or a plot without its axes is incomplete evidence.

The notebooks contain their own installation and path instructions. For a local terminal, use the repository's uv environment workflow. For a hosted notebook, follow its setup instructions before running the imports. Restart the runtime and run all cells in order before sharing your work; old variables can hide mistakes.

The eight guides

Guide Main question Core checkpoint
1 · Foundations What do shape, axes and dtype mean? Read one image pixel and explain a batch shape.
2 · Labels and counts What exactly are we counting? Separate images, image–class pairs, pixels and regions.
3 · RLE and geometry Does the decoded mask occupy the right places? Hand-decode a small RLE and inspect an aligned overlay.
4 · Intensity and texture Can brightness alone identify this region? Explain two patterns with the same histogram.
5 · Metrics What does this score reward? Compute Dice and explain an empty-mask convention.
6 · Validation Have we tested on genuinely held-out examples? Split by source image and audit rare-label support.
7 · Diagnostic baseline What can a deliberately simple rule teach us? Compare trivial predictions and explain a threshold change.
8 · Practice and resources How do we practise and transfer the reasoning? Complete the evidence checklist and explain limitations.

Our practice data

We use Understanding Clouds from Satellite Images, a separate Kaggle competition about cloud organisation. Its four labels are Fish, Flower, Gravel and Sugar. This gives us real images, multiple labels, RLE and empty class masks without supplying the industrial project's data analysis or solution. The dataset guide explains access, annotation meaning, geometry and limitations.

Cloud labels describe organisation regions; they are not precise masks of every visible cloud. Cloud scores, class frequencies, preprocessing choices and useful thresholds do not establish anything about industrial defects. The small toy examples in these notes are invented for explanation. The notebooks do not import the industrial project pipeline, models, splits or results.

A manageable learning route

During the teaching session: follow the “Core” sections and answer one checkpoint per guide. The instructor runs selected notebook cells. A complete individual data download, all exercises and a full audit do not fit into a two-hour lecture.

If you are catching up: finish Guides 1–3 first, then the Dice example in Guide 5. Ask a peer to check one mask by hand. Continue with the split and baseline after those objects make sense.

After the session: read the chapters over several study sittings and do the longer practice tasks in Guide 8. The depth here exceeds what can be demonstrated in 110 minutes of teaching plus a 10-minute break. Reconstruct the arithmetic and code examples before checking the worked answers. Sections labelled Optional extension or Optional depth can wait. No advanced reading is required to complete the core checkpoints.

What belongs in your notebook

  • A shape/range/dtype check and one correctly aligned image–mask overlay.
  • A table whose counts identify their units and denominators.
  • A distinction between image-level co-occurrence and actual pixel overlap.
  • A hand-checked Dice example and a stated empty-mask convention.
  • A saved image-level split with class support and overlap checks.
  • A simple baseline record with its limitations, rather than an unsupported performance claim.

When you return to your assessed project, repeat the checks on its own documented conventions. Write your own observations and conclusions. The transfer questions teach the method without providing assessment answers.
