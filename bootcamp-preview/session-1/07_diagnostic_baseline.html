7 · Let a simple baseline expose mistakes

Core question: what does this prediction rule know, and what can it never learn?

A baseline is a reference rule simple enough to explain. It helps establish whether the data, split and metric behave sensibly before a complex model obscures mistakes. A baseline need not be a neural network and need not qualify for a project cutoff. Today's aim is to produce a trustworthy comparison and an honest account of its limits.

Core · Begin with predictions whose meaning is obvious

Use the same validation images, target geometry and metric conventions for every rule:

Rule Information used What it tests
All empty No image content Whether empty-pair rewards hide complete failure to find foreground.
All foreground No image content Whether positive-case coverage comes with unacceptable false alarms.
Train-only spatial prior Training masks and coordinates Whether a repeatable location bias explains part of the annotations.

A random rule can also be useful if its seed and foreground probability are declared. It is optional here. None of these rules understands cloud appearance. A nonzero Dice value does not prove that image features have been learned.

Do not choose a baseline by looking for one flattering scalar. Inspect positive-pair Dice, class-wise support, empty-pair behaviour, predicted area and representative overlays. Verify the manual examples from Guide 5 before interpreting a baseline result.

Core · Understand a spatial prior

At each location and for each class, average the training binary masks:

\[ s_k(y,x)=\frac{1}{N_{\mathrm{train}}} \sum_{i\in\mathrm{train}} M_{i,k}(y,x). \]

Here i identifies a training image, k a class and (y,x) a location on the shared teaching canvas. Empty class masks contribute zeros and remain in the denominator. A value of 0.25 means that location is marked for the class in a quarter of training images. It does not mean a new pixel has a calibrated 25% probability of the class.

For a toy location with training values [1, 0, 1, 0], the prior score is 0.5. If the next location has [0, 0, 0, 1], its score is 0.25. A threshold of 0.4 marks the first location and not the second.

The rule repeats the same class score map for every validation image. It can detect location bias but cannot adapt to a particular photograph. Two different images receive the same prediction at the same coordinates. This limitation is a valuable explanation, not a bug to conceal.

The practice notebook uses this deliberately small, train-only diagnostic. Decode masks with the correct geometry for the explicitly selected source variant, then resize to the notebook's aspect-preserving teaching geometry. The resulting local score is not the original competition's leaderboard evaluation.

Core · Train a small image-dependent model

Diagnostics tell us whether the checks work. A trainable starter baseline adds a different question: can image values help predict a supplied mask? The starter pixel-model notebook fits four independent logistic classifiers on the cloud practice data, using the saved training and validation image IDs from the data-audit notebook. Its paired script follows the same steps. It needs only a CPU and the same small set of libraries.

For one pixel with scaled red, green and blue intensities, one class uses

\[ z = w_R R + w_G G + w_B B + b, \qquad p = \frac{1}{1+e^{-z}}. \]

The three weights and bias are fitted parameters. z is a logit, an unconstrained score; sigmoid maps it to 0–1. Four classes get four independent sets of weights. Unlike a spatial prior, this model receives the new image's values, so different photographs can produce different masks. Unlike a U-Net, it sees no neighbouring pixels. Identical RGB values receive identical scores even when their surrounding texture differs.

A training step follows a small repeatable sequence:

  1. Read pixels and binary targets from training images only.
  2. Compute logits and probabilities from the current weights.
  3. Calculate binary cross-entropy: a loss that penalises confident disagreement with the targets.
  4. Compute how changing each weight changes that loss. These derivatives are the gradients.
  5. Move weights a small amount opposite the gradients: weight -= learning_rate * gradient.
  6. Repeat for a declared budget; evaluate on held-out images without changing weights from their targets.

For a single binary target, BCE can be written stably from its logit as logaddexp(0, z) - target*z. Its derivative with respect to z is sigmoid(z) - target. The notebook shows how these errors become weight gradients through the input pixels. You do not need to derive calculus during the first session: trace one prediction, its error and the direction of the update. The live example below uses just one intensity feature and one training example so every number can be followed.

Start with zero weights: logit 0 gives probability 0.5. For a target of 1, the error p−target is negative, so a gradient-descent step increases the logit on that same example. This teaches an update, not generalisation.

Keep training loss separate from validation Dice. BCE uses continuous scores while hard Dice uses thresholded masks. A decreasing loss on training pixels does not guarantee better localisation on new images. Inspect the held-out errors and compare against the same empty/prior diagnostics. No weights, results or threshold from this cloud exercise should be transferred to the assessed project.

This deliberately weak starter model covers the first milestone's baseline-training idea. The later pipeline session develops spatial context, U-Net, batches, augmentation and a fuller training workflow. Finishing the small model independently can take longer than its in-class introduction.

Core · A score becomes a mask through a decision rule

prediction = score_map >= threshold

A score map and a binary prediction are different objects. Record the comparison operator: values equal to the threshold are selected by >=. A threshold is an operating choice, not the qualifying cutoff mentioned in project rules.

Consider one invented four-location example:

Target:          1     1     0     0
Score:          .9    .4    .6    .1
Threshold (>=) Prediction TP FP FN Dice
0.3 1 1 1 0 2 1 0 4/5 = 0.8
0.5 1 0 1 0 1 1 1 2/4 = 0.5
0.8 1 0 0 0 1 0 1 2/3 ≈ 0.667

Raising the threshold removes selected locations. It cannot increase the selected set when scores are fixed. TP and FP cannot increase, while FN cannot decrease. Recall therefore cannot increase for a nonempty fixed target. Dice can move either way, and precision is not guaranteed to rise at every step: it depends on which locations were removed.

There is no theorem that 0.5 is best for Dice, even for well-calibrated probabilities. The best threshold depends on the objective, score behaviour and evaluated population. With an uncalibrated spatial prior, treating 0.5 as inherently special is even less justified.

Core · A small, declared threshold comparison

For the teaching lab, compare a few thresholds already listed in the notebook. Fit the prior once on training masks. Apply each threshold to its validation score maps, without refitting from validation targets. For each candidate, record:

  • Threshold and target/evaluation shape.
  • Positive-pair Dice and the number of positive pairs behind it.
  • Empty-pair accuracy and the number of empty pairs behind it.
  • Mean predicted foreground area and several unchanged example IDs for overlays.

Do not claim that one score “should” peak at a higher threshold without checking the actual outputs. Empty-pair false positives shrink as the fixed threshold increases, but foreground overlap can rise, fall or remain tied. Keep the entire small table and explain errors; choosing only the winning row loses the learning evidence.

If you select a threshold using this table, name it a validation-selected setting. Its score on that same table is not a fresh independent test. Threshold tuning belongs on validation data, with final evaluation kept separate where possible.

Core · Diagnose surprising results

Observation First check Possible explanation after checks pass
Every prediction is empty Score range, threshold, units A conservative rule selected no locations.
All examples show the same mask Which baseline is running This is expected for a spatial prior.
Excellent all-pair Dice but poor overlays Empty convention and support Empty pairs can dominate an all-pair mean.
A class has no reported positive Dice Validation support There may be no positive examples for that class.
A dramatic improvement after changing shapes Decode/resize/target alignment A geometry bug may have changed what was measured.
Results change after rerunning cells Kernel state, IDs and seed Old variables or a regenerated split may be involved.

An unexpected result is a prompt for inspection. Avoid fixing it by immediately making the model larger. A complex model trained on shifted masks is still being taught the wrong answer.

Practice · Write a baseline record

Use four sentences:

  1. “The rule used ___ information, fitted on ___ IDs.”
  2. “It was evaluated on ___ pairs at ___ geometry with ___ empty convention.”
  3. “Its main failure was , shown by .”
  4. “A justified next experiment would test ___ because ___.”

Checkpoint: could a spatial prior tell two validation photographs apart? Could adding validation masks to its average improve the printed score while invalidating the comparison? Explain both without referring to a neural network.

Explanation

The prior uses coordinates, not image content, so it cannot adapt to two different photographs. Including validation masks would let examined answers influence the fitted rule. A higher resulting value would no longer measure held-out generalisation.

Optional extension · What comes next

A learned image model can use appearance and context to produce image-dependent scores. Later sessions extend this first update into Dataset/DataLoader contracts, aligned augmentation, optimisers and a spatial segmentation training loop. Today, identify one limitation such a model might address and one limitation it would not automatically fix, such as a wrong RLE convention or leaked split.

Transfer question: before training on another dataset, what trivial rules and hand checks would establish that your metric and data loading are trustworthy? Do not transfer the cloud prior, score values or threshold choices to the assessed task.
