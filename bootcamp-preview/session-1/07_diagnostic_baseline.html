7 · Let a simple baseline expose mistakes

Core question: what does this prediction rule know, and what can it never learn?

A baseline is a reference rule simple enough to explain. It helps establish whether the data, split and metric behave sensibly before a complex model obscures mistakes. A baseline need not be a neural network and need not qualify for a project cutoff. Today's aim is to produce a trustworthy comparison and an honest account of its limits.

Core · Begin with predictions whose meaning is obvious

Use the same validation images, target geometry and metric conventions for every rule:

Rule Information used What it tests
All empty No image content Whether empty-pair rewards hide complete failure to find foreground.
All foreground No image content Whether positive-case coverage comes with unacceptable false alarms.
Train-only spatial prior Training masks and coordinates Whether a repeatable location bias explains part of the annotations.

A random rule can also be useful if its seed and foreground probability are declared. It is optional here. None of these rules understands cloud appearance. A nonzero Dice value does not prove that image features have been learned.

Do not choose a baseline by looking for one flattering scalar. Inspect positive-pair Dice, class-wise support, empty-pair behaviour, predicted area and representative overlays. Verify the manual examples from Guide 5 before interpreting a baseline result.

Core · Understand a spatial prior

At each location and for each class, average the training binary masks:

\[ s_k(y,x)=\frac{1}{N_{\mathrm{train}}} \sum_{i\in\mathrm{train}} M_{i,k}(y,x). \]

Here i identifies a training image, k a class and (y,x) a location on the shared teaching canvas. Empty class masks contribute zeros and remain in the denominator. A value of 0.25 means that location is marked for the class in a quarter of training images. It does not mean a new pixel has a calibrated 25% probability of the class.

For a toy location with training values [1, 0, 1, 0], the prior score is 0.5. If the next location has [0, 0, 0, 1], its score is 0.25. A threshold of 0.4 marks the first location and not the second.

The rule repeats the same class score map for every validation image. It can detect location bias but cannot adapt to a particular photograph. Two different images receive the same prediction at the same coordinates. This limitation is a valuable explanation, not a bug to conceal.

The practice notebook uses this deliberately small, train-only diagnostic. Decode masks with the correct geometry for the explicitly selected source variant, then resize to the notebook's aspect-preserving teaching geometry. The resulting local score is not the original competition's leaderboard evaluation.

Core · Train a small image-dependent model

Diagnostics tell us whether the checks work. A trainable starter baseline adds a different question: can image values help predict a supplied mask? The starter pixel-model notebook fits four independent logistic classifiers on the cloud practice data, using the saved training and validation image IDs from the data-audit notebook. Its paired script follows the same steps. It needs only a CPU and the same small set of libraries.

For one pixel with scaled red, green and blue intensities, one class uses

\[ z = w_R R + w_G G + w_B B + b, \qquad p = \frac{1}{1+e^{-z}}. \]

The three weights and bias are fitted parameters. z is a logit, an unconstrained score; sigmoid maps it to 0–1. Four classes get four independent sets of weights. Unlike a spatial prior, this model receives the new image's values, so different photographs can produce different masks. Unlike a U-Net, it sees no neighbouring pixels. Identical RGB values receive identical scores even when their surrounding texture differs.

A training step follows a small repeatable sequence:

  1. Read pixels and binary targets from training images only.
  2. Compute logits and probabilities from the current weights.
  3. Calculate binary cross-entropy: a loss that penalises confident disagreement with the targets.
  4. Compute how changing each weight changes that loss. These derivatives are the gradients.
  5. Move weights a small amount opposite the gradients: weight -= learning_rate * gradient.
  6. Repeat for a declared budget; evaluate on held-out images without changing weights from their targets.

For a single binary target, BCE can be written stably from its logit as logaddexp(0, z) - target*z. Its derivative with respect to z is sigmoid(z) - target. The notebook shows how these errors become weight gradients through the input pixels. You do not need to derive calculus during the first session: trace one prediction, its error and the direction of the update. The live example below uses just one intensity feature and one training example so every number can be followed.

Start with zero weights: logit 0 gives probability 0.5. For a target of 1, the error p−target is negative, so a gradient-descent step increases the logit on that same example. This teaches an update, not generalisation.

Keep training loss separate from validation Dice. BCE uses continuous scores while hard Dice uses thresholded masks. A decreasing loss on training pixels does not guarantee better localisation on new images. Inspect the held-out errors and compare against the same empty/prior diagnostics. No weights, results or threshold from this cloud exercise should be transferred to the assessed project.

This deliberately weak starter model covers the first milestone's baseline-training idea. The later pipeline session develops spatial context, U-Net, batches, augmentation and a fuller training workflow. Finishing the small model independently can take longer than its in-class introduction.

Three baselines that answer different questions

A class-global pixel prior is a useful bridge between the all-empty rule and the spatial prior. For class k, count its marked pixels in the training images and divide by all training canvas pixels: q_k = marked pixels/(N_train × H × W). Repeat that one value at every location of every validation image. Do not confuse it with the fraction of images containing the class; a rare large region and many tiny regions can reverse those rankings. If q_k=0.08, a threshold of 0.5 predicts that class empty everywhere. That result diagnoses the combination of class imbalance and decision threshold; it does not show that an image has no cloud pattern.

The spatial prior replaces one class-wide value with an H×W map for each class. A training image contributes either zero or one at each location. The map can learn a repeated annotation location, but it still sends the same map to two completely different validation photographs. The trainable RGB pixel model is the first rule here whose output changes with a new image's colours. It cannot use nearby pixels, though, and so cannot tell a white pixel inside a thin structure from an equally white pixel in a different texture. These three rules should be compared on the same held-out IDs and grid, with their information sources named. It would be misleading to claim that any one is a full segmentation system.

Rule Fitted from training labels? Reads each new image? Retains location? Can read neighbours?
Class-global prior Yes, one value per class No No No
Spatial prior Yes, one map per class No Yes No
Four-head RGB logistic model Yes, four feature weights per head Yes No, except through the pixel value No

In all three, a score still needs a threshold to become a binary mask. A low or high numerical score need not be a calibrated probability. The spatial prior's observed frequency at a coordinate is estimated from a small sampled training set; it is not a trustworthy conditional probability for a new image. A logistic output lies between zero and one by construction, but that shape alone does not certify calibration either.

Trace the actual notebook arrays

The offline foundations notebook uses tiny synthetic arrays to teach HWC, CHW, RLE, masks and Dice. Its examples are not cloud measurements. The real-data practice notebook reads Image_Label/EncodedPixels, groups four rows per image, verifies the chosen Kaggle variant's geometry, checks a real overlay and splits image IDs once with a fixed seed. Its spatial prior averages up to 12 training masks at a 70×105 grid and evaluates up to 6 validation images. The saved session1_evidence.json includes the actual IDs, variant, split seed, grid and diagnostic cutoffs. On a limited smoke run these numbers may be smaller; the output explicitly says so.

The starter pixel-model notebook reads that manifest rather than drawing a new split. For each selected image, it resizes RGB input by bilinear interpolation, scales bytes to [0,1], and decodes each class's RLE at the selected source variant's native canvas. It then resizes binary masks by nearest neighbour to the same 70×105 grid. One image yields an RGB array (70,105,3) and binary targets (70,105,4). Flattening gives 7,350 pixel rows. The feature vector is [1,R,G,B], so a selected set of N images gives X shape (7350N,4) and Y shape (7350N,4). The leading 1 is the bias feature; it is not a fourth colour channel.

The weight matrix W has shape (4,4): four input features by four independent class heads. XW has shape (7350N,4). Each column receives its own sigmoid; the four outputs need not sum to one. That matters when two cloud categories mark the same pixel. A softmax would force a single winner and change the problem represented by the supplied labels. The starter code avoids a large framework to keep this relationship visible; its four-feature contraction is mathematically the same X @ W operation. There is no convolutional neighbourhood, decoder, pretrained encoder or GPU training in these Session 1 notebooks.

The local notebook requires the real practice manifest first. If it reports missing session1_evidence.json, run the practice notebook on the same selected variant and CLOUD_OUTPUT_ROOT; do not fabricate a split file. If it reports an incompatible variant, fix the dataset root or selection rather than changing expected dimensions to bypass the check. The starter saves a separate starter_pixel_model_evidence.json containing its exact selected IDs, shapes, learning settings, loss trace and diagnostic table, without copying image pixels or masks.

Work one gradient update by hand

For one pixel, let x=[1,0.2,0.4,0.6] and its four targets be y=[1,0,0,0]. Start with every weight at zero. Each logit is z_k=x·W[:,k]=0, and each sigmoid score is p_k=0.5. For one example and four classes, the notebook's mean BCE is

\[L=\frac14\sum_{k=1}^4[\log(1+e^{z_k})-y_k z_k]=\log 2\approx0.6931.\]

The derivative of this mean loss for weight W[f,k] is x_f(p_k−y_k)/4. The first class has error −0.5; each absent class has error +0.5. With teaching learning rate 2, the first head's bias update is −2×(−0.5/4)=+0.25. Each absent head's bias becomes −0.25. The first head's red weight becomes +0.05, green +0.10 and blue +0.15; the absent heads get the corresponding negative values. Recompute the first logit:

\[z_1=0.25+0.05(0.2)+0.10(0.4)+0.15(0.6)=0.39,\]

so its new sigmoid score is about 0.596. The other three logits are −0.39 and their scores about 0.404. The update moved this training pixel's scores toward its target. It did not show that the rule works on another photograph. The real notebook averages over a minibatch of many pixels and all four heads, so its gradient is Xᵀ(sigmoid(XW)−Y)/(4M) for M minibatch pixels. It uses a fixed shuffle seed and training IDs only for updates.

logaddexp(0,z)−yz is a stable way to calculate BCE from a logit, avoiding an explicit log(sigmoid(z)) that can fail at extreme values. Sigmoid is used for the gradient and later thresholding; targets remain 0 or 1. Resizing targets by bilinear interpolation would create fractional edge labels and change this binary exercise. Scaling RGB bytes to [0,1] is a fixed arithmetic transform, not a mean and standard deviation estimated from validation images.

An epoch is one pass through the selected training images. A minibatch is the subset used for one update. The notebook uses a fixed small image cap, two images per update and 12 epochs so the exercise runs on a CPU. These counts are classroom settings, not recommendations for another dataset or a proof of convergence. It evaluates validation BCE after each epoch but does not use validation masks in the weight gradient. An optimizer that selected the best epoch would use validation for selection and must record that additional choice; this notebook simply shows the short trace.

Follow a full training pass and a fixed validation pass

The starter's NumPy loop has no hidden training mode: only an explicit assignment to W changes its parameters. In a larger PyTorch model, dropout and batch normalisation also behave differently during fitting and evaluation. model.eval() changes those behaviours; torch.no_grad() disables gradient tracking. Neither replaces the other, and neither chooses a threshold or computes a metric automatically.

This framework sketch shows the boundaries. It assumes a four-logit model, a training and validation loader, and a mean-reduced BCEWithLogitsLoss; it is a reading example rather than another downloadable training notebook.

for epoch in range(number_of_epochs):
    model.train()
    for images, targets in training_loader:
        optimizer.zero_grad()       # remove the previous step's gradients
        logits = model(images)      # [B,4,H,W], targets have the same shape
        loss = loss_function(logits, targets.float())
        loss.backward()             # calculate parameter gradients
        optimizer.step()            # only training targets drive this update

    model.eval()
    with torch.no_grad():
        for images, targets in validation_loader:
            logits = model(images)
            scores = logits.sigmoid()
            predictions = scores >= declared_threshold
            # Accumulate per-pair counts/metrics with the stated empty rule.
            # No optimizer.step(), backward(), or fitting from these targets.

Gradients accumulate by default in PyTorch; resetting them prevents an unintended sum across unrelated steps. Evaluation targets are still needed to calculate errors, but they do not drive parameter updates. Dropout is disabled in evaluation and batch normalisation normally uses its stored training statistics. Forgetting to restore model.train() for the next pass can change subsequent training. The PyTorch optimisation tutorial walks through these operations in a larger example.

For loss summaries, account for batch sizes. If two batches contain 2 and 1 images and their mean losses are 0.2 and 0.8, the unweighted mean of batch means is 0.5, while the image-weighted mean is (2×0.2+1×0.8)/3=0.4. With equal grids/channels, image weighting also weights the elementwise mean correctly. Unequal valid-pixel counts require those counts instead. Hard Dice needs its own declared pair/class reduction; do not apply the loss averaging rule by reflex.

Separate learning, decision and generalisation

Loss and hard-mask Dice answer different questions. BCE uses every continuous score, so moving a true pixel from 0.30 to 0.45 improves its loss even if both are below a 0.5 hard-mask cutoff. A threshold can make the binary mask unchanged across several epochs while BCE steadily falls. Conversely, one score crossing 0.5 can change many pixels at once on a coarse annotation. Class imbalance gives the abundant absent pixels many contributions to mean BCE; a model can reduce average loss while missing a rare class. That is why the starter prints training and validation positive-pixel fractions and reports foreground-pair Dice beside absent-pair accuracy.

Consider invented epoch summaries below. They are not measured notebook results.

Epoch Training BCE Held-out BCE Interpretation to test
1 0.69 0.70 Starting point; masks and support still need inspection.
2 0.58 0.62 Both improve; evidence of learning, not yet of useful localisation.
3 0.47 0.55 Held-out BCE improves more slowly.
4 0.42 0.60 Possible overfit or unstable small holdout; inspect fixed examples and IDs.

Do not diagnose “overfitting” from the table alone: a few validation images, an absent rare class or a shifted source can make a curve noisy. Check whether the same source leaked across partitions, whether masks align, how many positive pairs support each number and whether examples were chosen in advance. Holding the split and images fixed makes a model comparison interpretable. Trying many seeds until one curve looks good turns the seed into another validation-selected choice.

Core · A score becomes a mask through a decision rule

prediction = score_map >= threshold

A score map and a binary prediction are different objects. Record the comparison operator: values equal to the threshold are selected by >=. A threshold is an operating choice, not the qualifying cutoff mentioned in project rules.

Consider one invented four-location example:

Target:          1     1     0     0
Score:          .9    .4    .6    .1
Threshold (>=) Prediction TP FP FN Dice
0.3 1 1 1 0 2 1 0 4/5 = 0.8
0.5 1 0 1 0 1 1 1 2/4 = 0.5
0.8 1 0 0 0 1 0 1 2/3 ≈ 0.667

Raising the threshold removes selected locations. It cannot increase the selected set when scores are fixed. TP and FP cannot increase, while FN cannot decrease. Recall therefore cannot increase for a nonempty fixed target. Dice can move either way, and precision is not guaranteed to rise at every step: it depends on which locations were removed.

There is no theorem that 0.5 is best for Dice, even for well-calibrated probabilities. The best threshold depends on the objective, score behaviour and evaluated population. With an uncalibrated spatial prior, treating 0.5 as inherently special is even less justified.

Read a threshold table from its counts

For the positive target in the four-location example above, at 0.3 the selected locations are 1, 2 and 3. Locations 1 and 2 are true positives, location 3 is a false positive, and there is no missed positive: Dice = 2×2/(2×2+1+0)=4/5. At 0.5, location 2 drops out, so TP=1, FP=1, FN=1, giving 2/(2+1+1)=1/2. At 0.8, location 3 also drops out: TP=1, FP=0, FN=1, giving 2/3. Dice improved between 0.5 and 0.8 because the removed false positive outweighed the unchanged missed positive. It did not recover the positive at location 2.

Now keep the exact same four scores but make the target all zero. At thresholds 0.3, 0.5 and 0.8 there is at least one false alarm, so that image/class pair gets Dice 0 under our explicit one-empty convention. At 0.95 every score is below the cutoff, prediction and target are both empty, and the pair gets 1. If we averaged this empty pair and the positive pair equally, the resulting toy all-pair means would be 0.4, 0.25, about 0.333 and 0.5 for cutoffs 0.3, 0.5, 0.8 and 0.95. The highest mean in this two-pair toy would belong to 0.95, despite zero foreground Dice at that cutoff. This is why the denominator and support population must accompany a reported score.

A cutoff comparison should use a small fixed list, the same validation images and the same underlying scores. Record a deterministic tie rule before looking at results; for example, prefer the less aggressive cutoff among tied diagnostic values, while showing both positive and absent-pair behaviour. One can inspect precision and recall too: precision is TP/(TP+FP) when there is a predicted positive, and recall is TP/(TP+FN) when there is a true positive. State how undefined denominators are handled. A higher threshold removes predictions, but it is not guaranteed to raise precision on every image. These are local teaching diagnostics, not a fitted threshold to carry into another competition.

Calibration asks whether a score such as 0.7 corresponds to about seven positives in ten comparable cases. That requires many independent held-out cases and careful grouping; the tiny Session 1 sample cannot establish it. A sigmoid maps a logit into [0,1] but does not make that empirical statement true automatically. Treat a calibration plot, if attempted later, as another validation analysis with its own data needs. For now, describe the score range, the chosen cutoff, target support and actual errors.

Core · A small, declared threshold comparison

For the teaching lab, compare a few thresholds already listed in the notebook. Fit the prior once on training masks. Apply each threshold to its validation score maps, without refitting from validation targets. For each candidate, record:

  • Threshold and target/evaluation shape.
  • Positive-pair Dice and the number of positive pairs behind it.
  • Empty-pair accuracy and the number of empty pairs behind it.
  • Mean predicted foreground area and several unchanged example IDs for overlays.

Do not claim that one score “should” peak at a higher threshold without checking the actual outputs. Empty-pair false positives shrink as the fixed threshold increases, but foreground overlap can rise, fall or remain tied. Keep the entire small table and explain errors; choosing only the winning row loses the learning evidence.

If you select a threshold using this table, name it a validation-selected setting. Its score on that same table is not a fresh independent test. Threshold tuning belongs on validation data, with final evaluation kept separate where possible.

Core · Diagnose surprising results

Observation First check Possible explanation after checks pass
Every prediction is empty Score range, threshold, units A conservative rule selected no locations.
All examples show the same mask Which baseline is running This is expected for a spatial prior.
Excellent all-pair Dice but poor overlays Empty convention and support Empty pairs can dominate an all-pair mean.
A class has no reported positive Dice Validation support There may be no positive examples for that class.
A dramatic improvement after changing shapes Decode/resize/target alignment A geometry bug may have changed what was measured.
Results change after rerunning cells Kernel state, IDs and seed Old variables or a regenerated split may be involved.

An unexpected result is a prompt for inspection. Avoid fixing it by immediately making the model larger. A complex model trained on shifted masks is still being taught the wrong answer.

Practice · Write a baseline record

Use four sentences:

  1. “The rule used ___ information, fitted on ___ IDs.”
  2. “It was evaluated on ___ pairs at ___ geometry with ___ empty convention.”
  3. “Its main failure was , shown by .”
  4. “A justified next experiment would test ___ because ___.”

Checkpoint: could a spatial prior tell two validation photographs apart? Could adding validation masks to its average improve the printed score while invalidating the comparison? Explain both without referring to a neural network.

Explanation

The prior uses coordinates, not image content, so it cannot adapt to two different photographs. Including validation masks would let examined answers influence the fitted rule. A higher resulting value would no longer measure held-out generalisation.

Optional extension · What comes next

A learned image model can use appearance and context to produce image-dependent scores. Later sessions extend this first update into Dataset/DataLoader contracts, aligned augmentation, optimisers and a spatial segmentation training loop. Today, identify one limitation such a model might address and one limitation it would not automatically fix, such as a wrong RLE convention or leaked split.

Transfer question: before training on another dataset, what trivial rules and hand checks would establish that your metric and data loading are trustworthy? Do not transfer the cloud prior, score values or threshold choices to the assessed task.
