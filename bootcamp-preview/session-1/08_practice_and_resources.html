8 · Practise on clouds, then transfer the reasoning

Core question: can I produce evidence and explain what it establishes?

The real-data exercise uses Understanding Clouds from Satellite Images, hosted on Kaggle. It is a separate task about cloud organisation, chosen because it has four labels, image–class RLE records and class-absent masks. It supplies realistic data-handling difficulties without providing the industrial project's analysis, fitted models or answers.

Core · Access and verify the practice files

Open the original competition, read its data page and rules, and obtain the files through your own authorised account. Kaggle may require sign-in and competition-rule acceptance. These materials do not accept terms or redistribute images on your behalf.

The official competition is the canonical source. The notebook also supports a named smaller Kaggle mirror so the CPU exercise can remain manageable. Its default is the 384 × 576 variant, not the original competition variant. Choose one coherent source and set the variant explicitly when changing it.

Notebook setting Source and exact geometry Default local folder
CLOUD_DATA_VARIANT=resized_384x576 (default) Kaggle resized mirror: height 384, width 576 for both images and its re-encoded masks data/bootcamp/clouds_384x576/
CLOUD_DATA_VARIANT=original Official competition files: height 1400, width 2100 for both training images and original masks data/bootcamp/understanding_cloud_organization/

In either case, CLOUD_DATA_ROOT selects the folder containing that variant's own train.csv and train_images/. You can edit the setup cell instead of using environment variables. The common semantic contract is:

Contract item Expected interpretation
Training table train.csv with Image_Label and EncodedPixels
Image key Filename plus final underscore-delimited class label
Class order for this lab Fish, Flower, Gravel, Sugar
Image content RGB photographs; exact dimensions depend on the named variant above
Training annotation canvas Must match the selected variant's CSV, not a geometry guessed from a filename
RLE interpretation One-based start–length pairs, down columns (F order)
Absent class Empty/missing EncodedPixels, interpreted as an all-zero mask after explicit CSV cleaning
Original submission geometry Height 350, width 525; this is distinct from original training geometry

The practice notebook validates dimensions, class records and RLE coordinate bounds. Point it to one variant's corresponding CSV and training-image folder. Keep downloads and generated results in your own local working area, outside committed teaching sources. Do not change an expected height or width merely to silence an assertion.

Dataset-variant trap: the supported mirror supplies re-encoded RLE at its resized geometry. A familiar filename and the same two column names do not prove compatibility. Never combine original labels with resized images, or the mirror CSV with original decoding dimensions. The mirror is not the official submission/scoring grid either. If neither authorised source is available, complete the offline foundations notebook, and record that the real-data audit remains pending. Synthetic practice is useful preparation, but it is not evidence about real cloud files.

The original download is access-gated and was not locally audited for these notes. A small mirror smoke check verifies execution, not a full visual audit. Use your account under the source's terms; the mirror's “Data files © Original Authors” label is not an unrestricted licence. No raw data is redistributed here.

Core · Understand what the labels mean

Fish, Flower, Gravel and Sugar name patterns of cloud organisation. They are not four colours, weather probabilities or industrial defect categories. The regional annotations are coarse and reflect human interpretation; a region can include spaces between visible clouds. Do not treat every annotated boundary as a precise physical cloud edge. The organisers' scientific paper describes the cloud-pattern labelling context and its limitations.

An absent class is different from an image containing no labelled class. Calculate image cardinality and class-absent pair counts separately. Do not assume the real dataset includes fully label-empty images simply because the toy table does.

The practice competition's metric and geometry also differ from the industrial task. A local small-canvas Dice diagnostic can validate code behaviour. It does not establish an official score or a transferable choice of model, threshold or noise filter.

Set up one complete run

Keep the selected dataset's train.csv and train_images/ together. The notebook's CLOUD_DATA_ROOT is their parent directory, not the CSV file itself and not a folder that contains another nested archive. The original Kaggle download may arrive as compressed image folders; extract them into train_images/ before running the file check. The resized mirror uses its own CSV with coordinates for 576×384 masks. Pick the variant before opening the practice notebook and write it in the evidence log.

For a local checkout, from the repository root, one explicit mirror run is:

export CLOUD_DATA_VARIANT=resized_384x576
export CLOUD_DATA_ROOT=data/bootcamp/clouds_384x576
export CLOUD_OUTPUT_ROOT=runs/bootcamp_session1_practice
uv run --no-project --with numpy==2.2.6 --with pandas==2.3.3 --with matplotlib==3.10.9 --with pillow==12.3.0 python docs/bootcamp_session_1/practice_dataset_lab.py
uv run --no-project --with numpy==2.2.6 --with pandas==2.3.3 --with matplotlib==3.10.9 --with pillow==12.3.0 python docs/bootcamp_session_1/starter_pixel_model.py

Use CLOUD_DATA_VARIANT=original and its corresponding root only for a complete original training CSV and original-size images. The starter command must follow the practice command because it reads the saved session1_evidence.json and reuses its exact train_demo_ids and validation_demo_ids. Do not edit those IDs by hand to improve a score. Both scripts write small JSON evidence records to CLOUD_OUTPUT_ROOT; the inputs remain untouched.

In Kaggle Notebooks, attach your chosen dataset, inspect its directory in Files, set CLOUD_DATA_ROOT to the folder containing CSV and JPEG directory, and write CLOUD_OUTPUT_ROOT under /kaggle/working/. In Colab, mount your authorised data in a persistent location and set both paths in the first cell or with os.environ; copy evidence out before the temporary runtime ends. Choose a Python 3 CPU runtime.

The notebooks import NumPy, pandas, Matplotlib and Pillow. Try imports first. If a package is missing in a hosted runtime, install the pinned version from the notebook setup with %pip, restart and Run All. Locally, use uv as above. The notebooks do not download data or accept Kaggle rules.

When a run stops, read the first useful error

Symptom Check and repair
Real cloud data missing or Missing ... train.csv Print the resolved CLOUD_DATA_ROOT; it must directly contain train.csv and train_images/. Check attachment/extraction and spelling.
Thousands of referenced JPEGs missing The full CSV was paired with only part of the image folder. Finish the authorised download. The four-ID smoke option is for a labelled code check, not a shortcut to a full analysis.
Expected 576×384 but image is 2100×1400, or RLE reaches beyond the canvas The variant, CSV and JPEGs disagree. Re-select the matching pair. Changing EXPECTED_SIZE alone would make the labels wrong.
Missing one of the four labels, unknown class, or duplicate row Inspect the exact CSV columns and Image_Label values. Confirm the selected file belongs to the named cloud source, then restore the unmodified source CSV.
Overlay looks striped, rotated or shifted Stop before interpreting counts. Check 1-based starts, F-order traversal, (height,width) shape and image-mask alignment using a small known RLE. An encode–decode round trip alone is insufficient.
Starter says the practice manifest is missing or incompatible Run practice first with the same CLOUD_OUTPUT_ROOT and CLOUD_DATA_VARIANT. Do not mix a prior manifest from another variant or runtime.
A diagnostic is NaN Print the positive/absent pair support. With no positive pair in a tiny sample, foreground Dice is unavailable; it is neither perfect nor failed.
A curve changes after rerunning only one cell Restart and Run All in order. Note the selected IDs and fixed seeds; stale notebook variables can give a plausible but unreproducible result.

CLOUD_SMOKE_IMAGE_IDS explicitly checks only named real JPEGs. Leave it unset for the normal full-data lab; smoke outputs cannot estimate prevalence or model quality.

Write a short evidence report

Keep the two JSON manifests with a one-page explanation. A useful report records source variant and file layout, native and teaching-grid dimensions, the RLE convention and one hand-checked pixel, four-class label order, original-image split IDs or manifest path, positive and absent support counts, and one overlay chosen without looking for a flattering result. Follow with a small comparison table for all-empty, spatial prior and trainable RGB pixel model. State which rules read the validation image, which were fitted on training labels, and what each rule cannot know. Include the short training BCE trace and the complete threshold table, including weak rows.

For every displayed number, write its denominator and image-ID population. Say “two positive image–class pairs among six sampled validation images” rather than “good Dice.” Distinguish a full-CSV presence count from a decoded-subset pixel-area estimate. Include one failure image and a plausible explanation you could test, such as a location prior repeating a mask on unrelated photographs. Do not select a different easiest image for each rule.

A peer-review rubric asks four questions: correctness (RLE, geometry and overlay), independence (source-group separation), interpretation (foreground and absent-pair support), and reproducibility (saved variant, IDs and settings). A weak baseline with sound evidence is a successful diagnostic. Compare the class-global and spatial priors in Guide 7 before proposing a richer model.

Guided practice · Evidence before explanation

Work with a partner if possible: one person predicts the output; the other runs the cell; then switch. Preserve your own notebook and explanations.

Task Evidence to keep Hint if stuck
1. Read one image Filename, shape, dtype, range and display Compare width/height with the documented source variant.
2. Audit the annotation table Column names, unique keys, label vocabulary and missing-mask handling Count images independently of CSV rows.
3. Decode one positive class Original mask and translucent overlay Hand-check a tiny RLE before debugging a large one.
4. Inspect an absent class Empty mask with full shape An empty target is still an array, not None.
5. Build a count sheet Counts with image/pair/pixel denominators Report full-table counts separately from decoded-subset estimates.
6. Compare two class masks Presence, union and intersection at native geometry Co-occurrence does not establish intersection.
7. Save a split Image-ID lists and support table Keep every class row and derivative of an image on one side.
8. Compare simple baselines Same validation IDs and declared diagnostic Explain what the spatial prior cannot observe.
9. Train a starter pixel model Train-only loss trace and held-out predictions Run the small trainable model after saving the practice split; it sees RGB, not spatial context.
10. Vary a threshold Small table and fixed example overlays More conservative does not imply higher Dice.

A lightweight lab may decode only a declared subset to stay responsive. Record exactly which IDs and how many masks were inspected. A subset's observed pixel coverage or overlap is not an exhaustive whole-dataset claim. Read all annotation metadata when feasible, but avoid holding every native mask in memory at once.

Independent exercises · After the teaching session

Exercise A: teach one RLE. Draw a non-square grid with two runs, including one crossing a column boundary. Give a peer only the RLE, shape and format contract. Compare their decoded grid with yours. If both encoders share a mistake, a round trip alone will not expose it.

Exercise B: challenge a claim. A fictional report says, “The baseline achieved 92% accuracy, so it detects small regions well.” Write two questions and propose one diagnostic. Hint: ask about foreground coverage, then calculate an all-background reference.

Exercise C: audit a split. Construct six toy image IDs with one singleton label combination. Explain why exact proportional representation of every combination is impossible. Write a policy before assigning the singleton. Never place a copy on both sides.

Exercise D: explain a threshold table. Use the four-location scores in Guide 7. Add a threshold of 0.95, compute the mask and Dice, and explain why its empty output is wrong for that target. Then consider an empty target with the same scores. Which error changes?

Exercise D explanation

At 0.95, no score passes, so the prediction is empty. On the two-positive target, TP = 0 and FN = 2, so Dice is zero. On an empty target it removes all false positives, producing empty–empty agreement under the exercise convention. The same decision rule has different consequences for positive and empty pairs.

Optional extension: explain one apparent success and one failure of the spatial-prior baseline using location bias and annotation geometry. Compare the trained RGB pixel model with the spatial prior, then propose a context-aware model hypothesis without implementing a full project pipeline.

Glossary for review

Term Plain-language meaning
Annotation / target A supplied answer against which predictions are compared.
Array / tensor Values arranged along named axes with a shape and dtype.
Batch Several examples grouped for one computation.
Binary mask A yes/no value at every image location.
Cardinality Number of present labels in one image.
Channel One axis of measurements or class scores; its meaning depends on the object.
Co-occurrence Two labels are present somewhere in the same image.
Pixel overlap The same location belongs to more than one class mask.
Connected component A foreground region connected under a stated neighbourhood rule.
Dice A foreground-overlap score with an explicitly chosen empty convention.
Dtype How numbers or Boolean values are stored.
Leakage Examined information influences fitting or invalidates an independence claim.
Normalisation A declared change of numerical scale; its exact meaning must be stated.
RLE A sequence of foreground start positions and run lengths.
Stratification Allocation intended to preserve chosen label proportions, subject to constraints.
Texture Spatial arrangement and local relationships among image values.
Threshold A decision boundary that converts scores into selected pixels.
Validation Held-out data used to assess and select development choices.

Transfer questions · Bring these to the assessed project

  1. Which fields, mask conventions and geometry must you verify from that dataset's own documentation?
  2. Which quantities must be counted from its own annotations rather than copied from cloud practice?
  3. How will you establish whether image-level labels imply pixel overlap?
  4. What independent source unit must remain on one side of the split?
  5. Which parts of its metric are precisely specified, and which require organiser clarification?
  6. What would falsify your explanation of a baseline's apparent success?

Answer with a planned check and the evidence it would produce. These are reasoning prompts, not supplied results for milestone questions.

Primary sources and optional further study

  • Cloud competition overview and evaluation, data and rules: dataset and access contracts. Check the current pages in your own account.
  • Supported 384 × 576 Kaggle mirror: smaller images and its own resized-mask CSV; source usage terms apply.
  • Organisers' cloud-pattern paper: why the region labels describe cloud organisation.
  • NumPy array indexing and reshape: axes, slices and traversal order.
  • PyTorch tensor tutorial: shape, dtype and device; optional after the NumPy exercises.
  • Pillow image API: image loading and explicit resize/resampling semantics.
  • Scikit-learn common pitfalls: leakage and training-only fitted transformations.
  • Original multi-label stratification paper: optional extension beyond combination-based splitting.
  • Metrics Reloaded: optional research reading about validation choices.
  • Understanding Deep Learning, author website: optional background on supervised learning and neural networks. Start with inputs, predictions, targets and generalisation; the core lab does not require completing a textbook.
