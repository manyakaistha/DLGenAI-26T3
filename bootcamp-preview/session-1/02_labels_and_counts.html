2 · Count images, labels and pixels separately

Core question: what is the denominator of this claim?

“There are many examples of this class” can refer to many annotation rows, many photographs or many pixels. Those statements have different implications. Before calculating a percentage, write its numerator and denominator in words.

Core · Classification, detection and segmentation

Classification answers which labels occur in an image. Detection adds approximate locations, commonly boxes. Semantic segmentation assigns a category or categories to locations in the image. A mask does not necessarily distinguish separate instances of the same category: two disconnected Fish regions can be stored in one Fish mask.

Multiclass classification chooses one class from mutually exclusive choices for a single decision. Multi-label classification permits several independent labels for the same example. An image can contain Fish and Sugar, so its image-level label can be [1, 0, 0, 1] in the fixed Fish/Flower/Gravel/Sugar order. That vector does not tell us whether Fish and Sugar occupy the same pixel.

Core · Read a long annotation table

The cloud practice CSV uses Image_Label to combine the image filename with a class label, and EncodedPixels for that class's mask. The notebook separates the final underscore-delimited label, checks the label vocabulary, and verifies that each image–class key is unique. Never split a filename at every underscore and assume the first piece is its complete name.

An empty annotation means “this class has no marked region here” under this dataset's convention. Preserve it as an empty mask. A missing image file, an invalid RLE and an empty target are three different conditions. An image is fully label-empty only if all its class masks are empty; one absent class does not make the whole image clean.

Use this invented presence matrix, not a measured cloud distribution:

Cardinality is the number of present labels in one image: sum across a row. It is not foreground area or the count of connected regions.

There are 5 images, 20 image–class pairs and 6 positive pairs. Four images have at least one label. Thus the label-positive image fraction is 4/5, while the positive-pair fraction is 6/20. Neither tells us foreground pixel coverage. Even when every real cloud image has some cloud label, individual image–class pairs may still be empty. Measure both quantities rather than transferring assumptions from another dataset.

Core · Three kinds of imbalance

  1. Image-label imbalance: one class occurs in few images. A model has fewer distinct positive examples from which to learn that class.
  2. Pair imbalance: many image–class questions have an empty answer. A model may learn that predicting absence is often rewarded.
  3. Pixel imbalance: a positive image can contain a small labelled area surrounded by background. Most pixel decisions can be negative even when image-level class counts seem balanced.

Suppose a toy mask covers 5 of 100 pixels. Predicting background everywhere has 95% pixel accuracy but detects none of its foreground. This is why an impressive accuracy figure needs a foreground-focused diagnostic. Guide 5 calculates one.

When reporting pixel coverage, specify whether it is sum(mask_k)/(N*H*W) for one class across all images or coverage only among positive images. They answer different questions. For overlapping labels, summing all class areas can exceed the union area; use a union when asking “what fraction of image locations has any label?”

Core · Co-occurrence and overlap are different audits

Draw a 3 × 4 grid. Mark Fish in the leftmost column and Sugar in the rightmost column. They co-occur in the image but share no pixels. Now move one Sugar pixel into the Fish column. The presence vector stays the same, while pixel overlap changes.

# masks is a stack of registered Boolean targets: (classes, height, width)
present = masks.reshape(masks.shape[0], -1).any(axis=1)
cardinality = present.sum()
occupancy = masks.astype(np.int16).sum(axis=0)
overlap_locations = (occupancy > 1).sum()
union_area = (occupancy > 0).sum()

present asks whether each class marks anywhere. occupancy asks how many classes mark each location. Report the number of images inspected as well as overlapping pixels. Finding no overlap in a handful of overlays is not proof that the full annotation set is disjoint. Check at native mask geometry; resizing can erase small overlaps or create artefacts.

Core · Why output semantics matter later

At a pixel, four independent sigmoid outputs answer four yes/no questions. They can all be low, or several can be high. A softmax distributes a total of one across mutually exclusive categories; a background-inclusive argmax selects one category. If a dataset permits overlapping targets, converting them to one class ID discards information.

For this session, keep four separate binary masks. You do not need to choose or implement a neural-network head. First establish what the annotations can represent. “Four labels” by itself does not imply a four-category softmax; it also says nothing about the input image's three colour channels.

Checkpoint · A small audit on paper

For the five-image toy table above:

  1. Count Fish-positive images, label-empty images and cardinality-two images.
  2. Add a second disconnected Fish region to image q. Which table entries change?
  3. Can the table establish whether image r contains overlapping masks?
  4. A class appears in 50 of 100 images, but covers 2% of each positive image. What fraction of all class-mask pixel decisions are positive, assuming equal image sizes?
Hints and explanations
  1. Fish-positive = 2; fully label-empty = 1; cardinality-two = 2. State that the denominator for each image count is five.
  2. Presence and cardinality do not change; mask area and possibly component count change.
  3. No. It records presence only. Decode the registered masks and test their intersection.
  4. 0.50 × 0.02 = 0.01, or 1% across all images for that class. This illustrates the difference between image prevalence and pixel prevalence.

Practice · Build a count sheet

In the practice notebook, label each output as image, pair, class or pixel. Record the full table size separately from a small decoded subset. Use filenames to join image and annotation records; an image reader's file order is not a reliable match to CSV row order. Keep zeros when making count plots so absent combinations do not disappear silently.

Optional extension: draw a class co-occurrence matrix whose entry (i, j) counts images containing both classes. Compare it with a pixel-intersection matrix. Explain why the two matrices need not have similar relative values.

Transfer question: in a new dataset, what evidence would justify saying “most examples are clean”? How would you distinguish unannotated material from explicitly labelled absence?
