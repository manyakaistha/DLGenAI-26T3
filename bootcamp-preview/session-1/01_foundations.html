1 · A notebook, an image and a tensor

Core question: what object am I holding, and what does each axis mean?

A photograph is a collection of measurements. A target mask records an answer supplied by an annotator. A model produces a proposed answer. Although all three can appear as colourful pictures, their numbers have different meanings. Understanding those meanings is the first step toward debugging a segmentation project.

You can learn this chapter without calculus or a GPU. Work through the small arrays before opening the foundations notebook. The examples are invented; their values are not observations about either competition dataset. Read the optional tensor section after the core exercises if Python is still unfamiliar.

1.1 · Inputs, targets, predictions and learning

In supervised learning, an example pairs an input with a target. For image segmentation, the input contains measured intensities and the target identifies annotated locations. We can write this as prediction = model(input). The model uses its current parameters, which are adjustable numbers, to calculate a prediction. A loss compares that prediction with the training target. Training updates the parameters to reduce that loss across training examples.

The target is not calculated from the current prediction. If the prediction is wrong, we do not move the annotation to agree with it. We inspect the error and, during training, adjust the model. Validation uses examples held out from fitting to examine whether the learned rule works beyond the examples it learned from. A metric summarises those examined predictions. Loss, prediction and metric are separate objects, even when they all appear as numbers in a notebook.

Today we first learn the model's inputs and answers. A mistake in their shape or meaning can remain hidden through a long training run. A fast, hand-checkable example is therefore useful preparation for a larger model.

1.2 · From one number to a grid

A scalar is one number, such as 140. A vector is a sequence, such as [10, 70, 140, 240]. A two-dimensional array arranges values along two axes. For an image grid, axis 0 usually counts rows and axis 1 counts columns. More axes allow colour channels, batches and other information. A tensor is a general term for such a multi-axis numerical object; it is not automatically a GPU object.

import numpy as np

image = np.array([
    [0, 64, 128, 255],
    [10, 70, 140, 240],
    [20, 80, 150, 230],
], dtype=np.uint8)

print(image.shape)       # (3, 4)
print(image.ndim)        # 2 axes
print(image.size)        # 12 stored values
print(image.dtype)       # uint8

The outer list contains three row lists. Each row contains four values. Thus shape is (3, 4), and multiplying the axis lengths gives size = 3 × 4 = 12. ndim counts axes, not rows. A two-dimensional array can have a million rows and still have two axes.

The same 3 × 4 shape could represent an image, a table of exam marks or part of a matrix calculation. Shape records organisation; the data contract supplies meaning. Write axis names beside an unfamiliar shape before manipulating it.

1.3 · Read coordinates and slices

Python starts counting at zero. image[1, 2] selects the second row and third column, whose value is 140. NumPy image indexing is commonly [y, x]: row first, column second. A drawing may describe a point as (x, y), so copying coordinates without naming their order is dangerous.

print(image[0, 3])          # 255: top-right value
print(image[:, 2])          # [128, 140, 150]: all rows, column 2
print(image[1, :])          # [10, 70, 140, 240]: row 1, all columns
print(image[0:2, 1:3])      # [[64, 128], [70, 140]]

A colon alone takes everything on an axis. The slice 0:2 includes indices 0 and 1 and excludes 2. The final selection therefore takes two rows and two columns. Its shape is (2, 2). This stop-before rule also matters when a later guide converts RLE lengths into Python slices.

Selecting one integer index removes that axis from the result: image[1, :] has shape (4,). A slice retains it: image[1:2, :] has shape (1, 4). These objects contain the same four values but have different shapes. Adding an axis does not add a new measurement; it changes the organisation expected by the next operation.

1.4 · Dtype changes what arithmetic can represent

dtype describes number storage. uint8 means unsigned 8-bit integer, with values from 0 through 255. float32 represents floating-point values, including fractions and negative values. bool represents false or true. The correct dtype depends on the object's role.

A stored 8-bit photograph may reasonably use uint8, but intermediate calculations often need floating point. For example, subtracting a brighter value from a darker one should give a negative difference. Unsigned arithmetic cannot represent that intended result. Convert before subtracting; do not assume that an integer array behaves like unrestricted mathematical integers.

a = np.array([10, 250], dtype=np.uint8)
change = a.astype(np.float32) - 100.0
assert np.allclose(change, [-90.0, 150.0])

astype creates a representation with the selected dtype. It does not decide whether the values represent brightness, labels or probabilities. Converting a binary mask to floating point leaves its values at 0.0 and 1.0; dividing it by 255 changes those values and therefore changes its target meaning.

1.5 · Colour, classes and batches occupy different axes

An RGB pixel contains three colour measurements, for example [0, 128, 255]. An RGB image reader commonly returns height × width × channels, abbreviated HWC. PyTorch image models commonly use channels × height × width, abbreviated CHW. A batch adds an example axis in front.

Object Example shape Interpretation
Grayscale image (3, 4) Three rows, four columns, one intensity at each location
RGB image, HWC (3, 4, 3) Three colour values at each of twelve locations
RGB image, CHW (3, 3, 4) The same colour measurements with channels first
Four binary target masks (4, 3, 4) Four membership questions at each location
Two RGB inputs, BCHW (2, 3, 3, 4) Two images, each with three colour channels

The repeated number 3 in these examples illustrates why values alone do not name axes. RGB's three channels describe colour. Four target channels describe four classes. There is no requirement that input and output channel counts match.

rgb = np.zeros((3, 4, 3), dtype=np.uint8)
rgb[1, 2] = [0, 128, 255]
chw = np.moveaxis(rgb, -1, 0)
assert chw.shape == (3, 3, 4)
assert np.array_equal(chw[:, 1, 2], rgb[1, 2, :])
batch = np.stack([chw, chw], axis=0)
assert batch.shape == (2, 3, 3, 4)

The assignment paints one known pixel. moveaxis relocates the last axis to the front while preserving that pixel's three measurements. stack adds an example axis. In contrast, reshaping HWC directly into CHW merely requests a different arrangement of the same sequence; it does not identify and move the colour axis. A compatible total element count does not prove a correct conversion. The NumPy reshape reference distinguishes shape changes from indexing order.

1.6 · A mask records membership

A binary mask has one value at every location: 1 means marked, 0 means unmarked. It can mark bright regions, dark regions or a texture whose mean brightness is ordinary. For a small invented example, use brightness to construct a mask:

mask = image >= 128
assert mask.shape == image.shape
assert mask.dtype == np.bool_
assert mask.sum() == 6
foreground_values = image[mask]
print(foreground_values)    # [128, 255, 140, 240, 150, 230]

The comparison operates separately at every location. The resulting Boolean array contains true where the condition holds. Summing Booleans counts true entries. Boolean indexing image[mask] gathers those selected intensities into a vector; it does not retain their original grid arrangement.

An empty mask still has the full spatial shape, but every value is zero. It says that this class has no annotated location. It is different from a missing image file or an annotation record that was never supplied. In the cloud practice dataset, one absent class does not make the whole image label-empty.

Keep display operations separate from data operations. A translucent overlay is a picture for inspection, not a replacement target. Fix binary-mask display limits at 0 and 1 so plotting software does not exaggerate a small numerical range. Inspect the source image and each class mask separately before combining colours.

1.7 · Scaling and standardisation are different operations

For a confirmed 8-bit image, dividing by 255 converts the available intensity range to 0–1:

x = image.astype(np.float32) / 255.0
assert x.shape == image.shape
assert 0.0 <= x.min() <= x.max() <= 1.0
assert np.isclose(x[0, 2], 128.0 / 255.0)

The value 128 becomes approximately 0.50196. Its unit changed, but its role is still brightness. It is not a 50.196% class probability. Check bit depth and range first: dividing an already scaled image by 255 again would shrink 1.0 to approximately 0.00392.

Standardisation instead subtracts a mean and divides by a standard deviation:

\[ x_{\mathrm{standardised}}=\frac{x-\mu}{s}. \]

The mean μ locates the centre of the chosen training measurements; the positive standard deviation s describes their spread. Subtraction centres values around zero; division expresses differences in units of that spread. Negative outputs are expected. Standardisation is not clipping and does not guarantee a range of 0–1.

Use an invented training vector [0, 0, 1, 1]. Its mean is 0.5 and its population standard deviation is 0.5. Training values become [-1, -1, 1, 1]. A held-out value of 0.75 becomes (0.75 − 0.5)/0.5 = 0.5 using the same training statistics.

train_values = np.array([0, 0, 1, 1], dtype=np.float32)
train_mean = train_values.mean()
train_std = train_values.std(ddof=0)
if train_std == 0:
    raise ValueError("Constant training values need a declared scaling policy")
valid_values = np.array([0.75], dtype=np.float32)
standardised_valid = (valid_values - train_mean) / train_std
assert np.allclose(standardised_valid, [0.5])

Estimating mean/std from training plus validation lets held-out inputs influence a fitted transformation. Estimate them on training only and reuse them. RGB standardisation often has one statistic per colour channel; state which axes were averaged. A per-image transformation is another policy and changes what brightness information remains. The fixed conversion /255 uses a declared sensor range rather than fitting a statistic from held-out data. Guide 6 develops the leakage boundary.

1.8 · Intensity, logit, probability and target

At one pixel, these four numbers could coexist:

Object Example Meaning
Scaled input intensity 0.80 A measured colour/intensity value on a chosen scale
Model logit 2.00 An unrestricted raw output score
Sigmoid output About 0.881 A probability-like model score derived from that logit
Binary target 1 Annotation says the class is present here

A logit can be negative or greater than one. Sigmoid converts it using 1/(1+exp(-z)); zero becomes 0.5. A threshold can turn the score into a hard mask, for example score ≥ 0.5. None of these operations turns an input intensity into a ground-truth label. Also, a model score of 0.8 does not by itself establish reliable 80% confidence. Guide 2 explains how multiple classes share, or do not share, their score system.

Practice · Read, calculate, diagnose

Exercise 1 · Coordinates and shape

Find image[2, 1], the shape of image[:, 1:3], and the difference between image[0] and image[0:1]. Explain without running the code first.

Worked answer

The value is 80. The slice keeps all three rows and two columns, so its shape is (3, 2). image[0] is the first row as a (4,) vector; image[0:1] retains a row axis and has shape (1, 4). Equal selected values do not imply equal shape.

Exercise 2 · Convert units

An 8-bit intensity is 64. Calculate its 0–1 value. Then standardise it using an invented training mean 0.25 and standard deviation 0.10 on that scaled range. Should the mask target 1 undergo those same calculations?

Worked answer

64/255 ≈ 0.25098; standardisation gives (0.25098−0.25)/0.10 ≈ 0.00980. The mask stays a membership value of 1, with dtype converted only if the matching loss requires it. Image units and target semantics are different.

Exercise 3 · Explain a batch

An RGB input batch has shape (5, 3, 96, 144). Four binary targets are supplied for every example. Give the target batch shape and explain why dividing the target by 255 would be wrong.

Worked answer

The target batch is (5, 4, 96, 144). Five examples and spatial locations match; the channel meanings differ. A present target would become 1/255 after division, which no longer expresses the intended binary answer.

Exercise 4 · Diagnose a plausible-looking output

A colleague replaces moveaxis with reshape, finds the expected shape and starts training. Which check would expose a possible mistake? Why is an expected shape insufficient?

Worked answer

Paint a known RGB pixel, reorder, and compare its three channel values at the same row/column, as in Section 1.5. Also display the reconstructed image. Reshape preserves element count but can mix colour and spatial positions. Training cannot establish that those positions were correct.

Optional extension · NumPy arrays and PyTorch tensors

A compatible NumPy array can become a PyTorch tensor through torch.from_numpy(x). Such conversion can share underlying storage: modifying one object may affect the other. A tensor also records a device and may participate in automatic differentiation. Those properties do not change what its axes mean.

For now, inspect .shape, .dtype and .device before learning gradients. The PyTorch tensor tutorial provides a guided introduction. Device transfers and automatic differentiation belong in the later pipeline session; completing the exercises here does not require them.

Transfer question: write the input shape, target shape, ranges, dtypes and axis meanings you would verify for a new dataset. Which checks require a known pixel or overlay rather than a printed shape alone?
