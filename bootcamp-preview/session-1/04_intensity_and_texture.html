4 · Brightness is one clue; arrangement is another

Core question: could two regions have the same intensity statistics but look different?

A bright region can be interesting, ordinary illumination or a display artefact. A texture can differ even when average brightness stays the same. Before selecting preprocessing or a model, inspect which cues are visible and which cues the annotation describes.

Core · Intensity describes values

For one grayscale region, a histogram counts how often each intensity occurs. The mean gives an average level; the standard deviation describes spread around that mean. Neither records where the values occur.

Take these two invented 4 × 4 patterns:

Pattern A                 Pattern B
0   0   255 255            0   255 0   255
0   0   255 255            255 0   255 0
0   0   255 255            0   255 0   255
0   0   255 255            255 0   255 0

Both contain eight zeros and eight values of 255. They have identical histograms, mean 127.5 and population standard deviation 127.5. One is divided into two blocks; the other alternates like a checkerboard. A function of only the pixel-value histogram cannot tell them apart. A spatial comparison can.

This is the elementary meaning of texture here: the arrangement, variation and relationships of values over a neighbourhood. Texture depends on scale. A checkerboard shrunk far enough can become a nearly uniform patch, so resolution choices affect the evidence available to a model.

Core · Compare neighbourhoods

import numpy as np

a = np.array([[0, 0, 255, 255]] * 4, dtype=np.float32)
b = np.array([[0, 255, 0, 255], [255, 0, 255, 0]] * 2,
             dtype=np.float32)

def neighbour_change(x):
    return np.abs(np.diff(x, axis=1)).mean()

print(a.mean(), b.mean())
print(neighbour_change(a), neighbour_change(b))

The horizontal-neighbour differences average to 85 for A and 255 for B. This deliberately simple feature exposes arrangement that the mean misses. It does not establish a general-purpose texture classifier. Rotating the patterns changes a horizontal-only feature; real images also contain noise, different scales and unrelated edges.

Cast integer images to a signed or floating type before subtraction. Unsigned 8-bit arithmetic cannot represent a negative difference in the intended way. A numerical result from the wrong dtype can look precise while describing the wrong computation.

Core · What brightness thresholding can and cannot show

A rule such as image >= t selects bright locations. On a toy image with a bright square against a dark uniform background, it may isolate that square. It will also select an equally bright background object. If the two patterns above are assigned different semantic labels, their shared brightness values cannot determine those labels independently of location or context.

Cloud organisation annotations are especially useful for this discussion. A bright cloud pixel and a labelled cloud-pattern region are different concepts. A mask can encompass spaces between clouds because its target is organisation. A brightness threshold should therefore be described as a diagnostic rule, not a valid ground-truth generator.

Core · Make an observation before proposing a transform

For one selected class, display the original image, its mask and an overlay. Then ask:

  • Is the annotated region brighter, darker or mixed relative to nearby background?
  • Is the boundary a sharp intensity edge or a region-level interpretation?
  • Does the pattern involve spacing, repeated structures or local roughness?
  • Is the same apparent cue visible across several examples and illumination conditions?
  • Could a resize remove the cue I am discussing?

Foreground versus background intensity summaries require a registered mask. A shifted mask produces misleading statistics even when the code is otherwise correct. Start with the overlay. Compare several individual examples before pooling every pixel into one distribution; large images or large masks can dominate a pooled result.

Core · Normalisation is not evidence of separation

Dividing an image by 255 changes units. It does not make an ambiguous label separable. Contrast enhancement changes how local brightness differences appear; it may strengthen useful structure, unrelated texture or noise. A more dramatic picture is not automatically a better input.

Use fixed display ranges when comparing before and after views. State whether a transform changes the image data or only the plotting scale. In the core route we inspect the original data and one simple statistic; preprocessing experiments belong after a trustworthy split and a reproducible baseline.

Checkpoint · Explain the two patterns

  1. Can A and B have different means? Calculate rather than judge by eye.
  2. Would a histogram plot distinguish them?
  3. Why can a convolutional feature use information that a single-pixel threshold cannot?
  4. A transformation makes a mask overlay look sharper. What evidence would establish that it helps prediction?
Hints and explanations
  1. Their means are equal: (8 × 0 + 8 × 255) / 16 = 127.5.
  2. No. Their counts at each intensity are identical.
  3. A neighbourhood operation can respond to arrangements such as alternation and edges. This does not guarantee it learns the right semantic rule; it makes that information available.
  4. Compare held-out predictions under a fixed split and matching budget, change only the transform, and inspect both scores and errors. Display attractiveness is not a validation result.

Optional extension · Effect sizes and local features

You can compare foreground and background means relative to their spread, or examine local variance and co-occurrence-based features. A small difference of means does not prove the absence of predictive information: spatial arrangement, colour and context may matter. A large difference does not prove a stable cue: illumination or annotation sampling may explain it. Do not interpret thousands of neighbouring pixels as thousands of independent examples.

For a concrete next step, rotate pattern B and recompute the horizontal statistic. Then add a vertical-neighbour statistic and explain how that changes the description. NumPy's diff documentation defines the axis-wise difference operation used above.

Transfer question: what observation would support testing an intensity-based diagnostic on another dataset? What observation would make you inspect texture or context instead? Phrase both as hypotheses to check.
