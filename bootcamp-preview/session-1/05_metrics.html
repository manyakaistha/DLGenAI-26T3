5 · Calculate a score you can explain

Core question: which errors does this number notice, and over which examples is it averaged?

A correct metric implementation can still answer the wrong question. “Dice” without an empty convention, averaging population and evaluation geometry is incomplete. A useful score report names those choices and includes simple predictions whose behaviour we already understand.

Core · Count four outcomes

Compare one binary prediction P with one binary ground-truth mask G at the same geometry:

Ground truth Prediction Name Meaning
1 1 True positive, TP A marked location was found.
0 1 False positive, FP An unmarked location was predicted.
1 0 False negative, FN A marked location was missed.
0 0 True negative, TN A background location stayed background.

Imagine a toy mask with five foreground locations. A prediction marks six locations, three of them correct. Then TP = 3, FP = 3 and FN = 2. Foreground recall is TP/(TP+FN) = 3/5. Foreground precision is TP/(TP+FP) = 3/6. Recall asks how much target was found; precision asks how much predicted foreground was correct. Empty denominators require their own stated convention.

Core · Dice measures overlap

For one pair of masks,

\[ \operatorname{Dice}(P,G)=\frac{2|P\cap G|}{|P|+|G|} =\frac{2TP}{2TP+FP+FN}. \]

Vertical bars count foreground pixels. In the toy example, |P| = 6, |G| = 5 and |P ∩ G| = 3, so Dice is 6/11, approximately 0.545. The factor of two accounts for the common foreground appearing in both set sizes in the denominator. Perfectly matching nonempty masks have Dice 1. Disjoint masks with at least one nonempty mask have Dice 0.

True negatives do not appear in this formula. Adding a large blank border can raise pixel accuracy while leaving Dice unchanged, if TP/FP/FN remain unchanged. This makes Dice useful for inspecting sparse foreground, though it cannot describe every error that matters.

import numpy as np

def dice_pair(prediction, target):
    prediction = np.asarray(prediction, dtype=bool)
    target = np.asarray(target, dtype=bool)
    if prediction.shape != target.shape:
        raise ValueError("Masks must have the same shape")
    denominator = prediction.sum() + target.sum()
    if denominator == 0:
        return 1.0   # explicit convention for this teaching exercise
    intersection = np.logical_and(prediction, target).sum()
    return float(2 * intersection / denominator)

This function measures one pair only. Averaging it is a separate decision. It also deliberately uses hard binary masks; a differentiable soft Dice training loss is a later topic.

Core · Empty masks are a policy decision

Target Prediction Our exercise value Reason
Nonempty Exact match 1 Full agreement.
Nonempty Empty 0 All foreground missed.
Empty Nonempty 0 No foreground overlap.
Empty Empty 1 by convention The raw ratio is 0/0.

Empty–empty Dice is not universally 1. Different tools omit empty pairs, return a chosen value or apply smoothing. Read the task specification and test your implementation. Adding a small epsilon does not remove the need to decide what should happen: adding it to numerator and denominator versus denominator only gives different empty–empty values.

For the cloud practice competition, the published metric uses mean image–label Dice with empty–empty agreement rewarded. A local Dice mean at the notebook's small teaching resolution is a local diagnostic; it is not a reproduced leaderboard result at the official evaluation geometry. See the cloud competition overview and its evaluation section for its format and scoring rules.

Core · Averaging changes the question

An invented batch has four image–class pairs: one target is positive and three are empty. An all-empty prediction has per-pair Dice [0, 1, 1, 1] under our convention, so its all-pair mean is 0.75. Its mean over target-positive pairs is 0. It has detected nothing. Both numbers are mathematically correct; they describe different populations.

Also distinguish mean of pair Dice values from pooled-pixel Dice. If one pair is tiny and another is large, averaging their scores weights each pair equally. Pooling TP/FP/FN first gives larger masks more influence. Neither operation can be inferred merely from the name Dice.

Report at least the number of positive and empty pairs alongside their separate diagnostics. A class with no positive validation examples has no positive-pair localisation evidence. Mark that case unavailable rather than silently calling it perfect. If a small sample has no empty pairs, empty-pair behaviour is likewise unmeasured.

Core · A project's official metric is a separate contract

The industrial project's evaluation description, archived by the instructor on 7 October 2026 from its competition evaluation page, describes a weighted score with 70% foreground Dice, 20% false-positive score and 10% empty-prediction accuracy. Verify current organiser rules if that page is unavailable or has changed. This is different from the cloud competition's Dice mean. The archived description alone does not specify every detail of foreground averaging, false-positive normalisation or empty-subset handling. Do not invent a precise local formula and label it the official scorer.

When an exact scorer is unavailable, identify what is confirmed, ask the organiser for missing definitions, and clearly label any local approximation. We use ordinary binary diagnostics for the practice notebook. They teach arithmetic and error analysis; they do not supply an official industrial score, all-empty score or assessment calculation.

For practice, consider a fictional metric 0.6 × positive_pair_Dice + 0.4 × empty_pair_accuracy. It gives different importance to errors than an all-pair Dice average. Before calculating it, write which subset supplies each term. This fictional rule is only an exercise in reading metric definitions.

Core · Thresholds and area filters change predictions

A threshold selects score locations with score >= threshold. A component-area filter removes selected connected regions below a specified size. One changes pixel decisions using scores; the other uses the geometry of the resulting mask. Neither operation improves a score by definition.

For a toy target with two components of 3 and 12 pixels, a perfect prediction initially has Dice 1. A rule removing components smaller than 5 pixels deletes the real 3-pixel component. Recall falls to 12/15 = 0.8, and Dice becomes 24/27, approximately 0.889. The same filter might remove a false alarm elsewhere. Inspect the trade-off on held-out data and report the area unit and connectivity. Pixel area changes with resolution, so a cutoff in one geometry is not directly portable to another.

We introduce filtering to recognise its effect. Selecting a project filter and building a post-processing pipeline belong in later sessions. Keep the initial baseline unfiltered so its behaviour remains easy to inspect.

Checkpoint · Score and interpret

  1. G = {1,2,3,4} and P = {3,4,5}. Find TP/FP/FN and Dice.
  2. A 100-pixel canvas has two positive pixels. What is all-background accuracy? What is its foreground Dice?
  3. Why can “mean Dice = 0.9” be insufficient evidence that small foreground regions are found?
  4. Can a tiny false-positive region on an empty pair receive full empty-prediction accuracy?
Hints and explanations
  1. TP = 2, FP = 1, FN = 2; Dice = 4/7, approximately 0.571.
  2. Accuracy is 98/100 = 98%; Dice is zero because both target pixels were missed.
  3. The empty convention, pair composition, class weighting and size distribution may hide poor foreground behaviour. Ask for positive-pair and class-wise evidence plus overlays.
  4. Under an exact-empty criterion it receives zero: some foreground was predicted. A pixel-fraction penalty can treat it differently. This is why the precise metric definition matters.

Optional extension · IoU and Dice

Intersection over union is TP/(TP+FP+FN). For a defined nonempty comparison, Dice = 2 × IoU/(1+IoU). Dice is at least IoU; they are equal at zero overlap and perfect overlap. Their numeric scales differ, so a Dice of 0.6 cannot be compared directly with an IoU of 0.6 as if the values meant the same quality.

For a research discussion of validation choices, see the original Metrics Reloaded paper. Read it after the hand examples, not as a prerequisite.

Transfer question: before implementing another task's metric, what examples would you hand-check? Include an empty pair, a missed nonempty target, a false positive and two unequal-size masks.
